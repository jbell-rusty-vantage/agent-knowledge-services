# knowledge_verification 2.2.0 (migration 0005): consumer notes

For application bindings (AI Engineer `aiengineer/ai-engineer-db-contract`, Biotech) and their SQL tests. The
component is installed by its own installer before the application's migrations; 2.0.0/2.1.0 installs upgrade by
applying `0005_signatures_review_and_outbox` only. Rows written before 2.2.0 are not revalidated (checks `NOT VALID`).

| Object | 2.2.0 contract | Consumer action |
| --- | --- | --- |
| `seal_signing_key` | Installation-level pinned Ed25519 public keys (`active` signs, `retiring` verifies only, `revoked` nothing). Owner-written only. | Pin the KS sealer's public key with the operator key ceremony (`pinSealSigningKey` in the PostgreSQL binding) before the first seal. |
| `seal_run(...)` | 12 arguments: `..., p_signer, p_signature_alg 'Ed25519', p_signing_key_id, p_signature bytea(64), p_signer_context jsonb`. The manifest must carry `snapshot`, `run.id` (= this run) and `predecessor.digest` (= committed head). Families per kind: verification `capture, claims, report, observations`; decision/admission `report, decisions`; correction `report, observations`. | The 9-argument function is dropped. SQL test fixtures that seal must pass the new arguments (e.g. AIDB `supabase/tests/research_report_v2_projection.sql`). |
| `use_decision` | `qualifiers_digest` is null for report subjects (no sentinel); new rows carry `normalized_values` (flat string/safe-integer/boolean/null) and `normalized_values_digest`, equal to `record.normalizedValues`. | Fixtures inserting decisions add both columns. |
| `admit_exact_use(p_tenant, p_id, p_digest, p_epoch, p_now default now(), p_normalized_values_digest default null)` | The 4-argument call still resolves. A presented normalized digest must match (`rejected / NORMALIZED_VALUES_MISMATCH`). A decision conditioned on `review_required` holds `REVIEW_REQUIRED` unless an approving adjudication binds its exact subject/effect/qualifiers digests under a grant that is still live and in scope. | AIDB `research.require_admitted_use` should forward `p_normalized_values_digest` (follow-up migration) and may map `NORMALIZED_VALUES_MISMATCH` to `EFFECT_CONFLICT` (today it falls in its `REVIEW_REQUIRED` branch). |
| `check_use_eligibility(p_tenant, p_id, p_digest, p_now)` | Read-only: the same rule at the current authoritative epoch; records and locks nothing. Granted to every capability role. | Official reads (BKS) call it instead of `admit_exact_use`. |
| `reviewer_grant.scope` | `{"uses": [...], "audiences": [...], "reportKinds": [...]}`, `"*"` explicit wildcard; `{}` qualifies for nothing. | Grants name their scope. |
| `adjudication` | New `use_decision_id`, `qualifiers_digest`, `grant_id`, `record`. With a decision, the trigger requires the decision's exact subject, effect and qualifiers digests and a live grant covering its use/audience/report kind. | Adjudications name the decision they review. |
| `dispatch_outbox` | Writer `INSERT` revoked: `enqueue_dispatch(...)` is the only path (admitted, unsuperseded decision for the same bound digest; payload is an inline `artifact_custody` row with `digest = payload_digest`). New columns: `bound_effect_digest, use_decision_id, revocation_epoch, marker_scheme, expected_marker_digest, ack_outcome, ack_record, graph_tx_ref, settled_at, settle_detail`; state `refused`. `claim_dispatches(..., p_target_binding)` filters by target and first revokes rows of invalidated/superseded decisions. `acknowledge_dispatch(..., p_ack_record jsonb)` only from `dispatched`, verifying the marker digest under `ks-intent-marker.v1` (precomputed) or `bks-intent-marker-digest.v1` (JCS `{format, payloadDigest, planDigest}`). `settle_dispatch(tenant, id, 'revoked' or 'refused', detail)` is the terminal not-applied path. Listing a decision in an invalidation closure revokes its pending dispatches. | Biotech binding (SV-11) enqueues and acknowledges through these functions. |
| `dependency_edge` | Reading fixed: `from` is upstream, `to` depends on it. | Bindings write edges in that direction. |
