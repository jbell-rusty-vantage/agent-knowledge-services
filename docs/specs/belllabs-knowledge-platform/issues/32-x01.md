# X01: Fold bounded database operations into canonical application surfaces

Linear: [OVE-106](https://linear.app/overtonbell/issue/OVE-106/ksp-x01-fold-bounded-database-operations-into-canonical-application)

Status: ready-for-agent; implementation not started.

## What to build

Consumers invoke schema/read/plan/apply/receipt operations through the canonical operation catalog without losing native behavior.

Owner: Shared KS application/transports and domain adapters.

## Acceptance criteria

- [ ] Move an additive complete vertical operation family through application, HTTP, MCP and CLI with parity.
- [ ] Retain native snapshot, authority, idempotency and receipt semantics; no internal cross-repository imports.
- [ ] Declared/unsupported operations remain fail-closed; replace executor-only exclusions only after real implementations exist.
- [ ] Migrate all configured callers with exact pins before legacy removal.
- [ ] Preserve replay/artifact bytes and existing tests; record the known missing historical receipt separately.
- [ ] Canonical discovery/composition preserves native agent contracts; replacing a language requires demonstrated equivalence and explicit migration, not a GraphQL wrapper.

## Blocked by

R01, R02, N01, N02

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
