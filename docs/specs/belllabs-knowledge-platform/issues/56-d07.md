# D07: Upgrade a compatible application release with in-flight work

Linear: [OVE-125](https://linear.app/overtonbell/issue/OVE-125/ksp-d07-upgrade-a-compatible-application-release-with-in-flight-work)

Status: ready-for-agent; implementation not started.

## What to build

An operator installs a pinned compatible release and preserves in-flight knowledge operations across service/worker upgrades.

Owner: Platform/domain release and database owners.

## Acceptance criteria

- [ ] Machine-validate service/client/native schema/query/policy/rubric/skill/provider/catalog and worker version compatibility.
- [ ] Consume common KS operational SQL through its single owner while preserving AI Engineer and Biotech schema authority.
- [ ] Use versioned workers/queues or compatible handlers so old work never replays against incompatible code.
- [ ] Prove additive upgrade, grants/custody, lease/cancellation/lost callback recovery and forward-repair/rollback limits in disposable environments.
- [ ] Keep interactive read capacity separate from heavy work and enforce per-app budgets/authority.
- [ ] Include qualified GraphQL executable-schema/operation-registry/SDK and v2 migration evidence; source SDL digest alone is not API or graph compatibility.

## Blocked by

V13, D06, P03, X01, X02, X03, G07

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
