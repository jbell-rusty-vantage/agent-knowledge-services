# R01: Answer familiar AI Engineer questions through direct and Fast retrieval

Linear: [OVE-96](https://linear.app/overtonbell/issue/OVE-96/ksp-r01-answer-familiar-ai-engineer-questions-through-direct-and-fast)

Status: ready-for-agent; implementation not started.

## What to build

A consumer opens an entity/content version directly or receives a bounded evidence-based answer without a schema sandbox.

Owner: AI Engineer domain binding.

## Acceptance criteria

- [ ] Direct reads call approved named queries with zero model calls and explicit snapshots/truncation.
- [ ] Fast combines admitted retrieval channels and optional synthesis; unsupported graph features reject rather than disappear.
- [ ] Return citations, unsupported facets, freshness and the actual route; no silent external acquisition.
- [ ] Cache keys bind authorization, query/profile and data/publication versions; revocation is rechecked.
- [ ] Measure warm/cold p50/p95, full cost and answer support over a fixed representative question set.
- [ ] Expose application entity reads through the custom PostgreSQL-backed API and typed client, preserving named queries and native clocks; the separate evidence retrieval executor must not be confused with skipped db-read retrieval operations.

## Blocked by

F02

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
