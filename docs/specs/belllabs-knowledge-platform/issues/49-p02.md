# P02: Compose Biotech saved research and knowledge into a product API

Linear: [OVE-116](https://linear.app/overtonbell/issue/OVE-116/ksp-p02-compose-biotech-saved-research-and-knowledge-into-a-product)

Status: ready-for-agent; implementation not started.

## What to build

Web, mobile and agents can save research and inspect a report/protocol/timeline with authorized graph evidence.

Owner: Biotech product API owner.

## Acceptance criteria

- [ ] Store private profile/preferences/notes/saved-research in app-owned PostgreSQL, not the public research graph.
- [ ] Return versioned content with its evidence, qualification and review state through typed clients.
- [ ] Implement idempotent save/revise and expected-revision conflict semantics.
- [ ] Use a minimal reference consumer view for report/protocol comparison and freshness display.
- [ ] Test tenant/entitlement/source-access separation and reconnect without replaying writes.
- [ ] Compose user-state services with Biotech entity reads through the qualified Neo4j GraphQL product contract; agent tools continue to use native executor/skills.

## Blocked by

F02, C02, R02, G05

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
