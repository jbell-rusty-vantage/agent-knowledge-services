# G02: Bound the first product GraphQL operations using actual schema semantics

Linear: [OVE-136](https://linear.app/overtonbell/issue/OVE-136/ksp-g02-bound-the-first-product-graphql-operations-using-actual-schema)

Status: ready-for-agent; implementation not started.

## What to build

Supported product queries have enforced execution bounds even on union relationships and expensive input shapes.

Owner: Biotech GraphQL owner.

## Acceptance criteria

- [ ] Implement declared operation admission and variable policies; a persisted hash registry must be trusted and server-enforced rather than confused with APQ caching.
- [ ] Handle union-target @limit exclusions, defaults, nested fanout, aliases/fragments, filter recursion, variable/input arrays, offsets, counts/aggregates and response bytes.
- [ ] Exercise rejects before database/provider effects and compare actual selected-query execution with cost assumptions; keep stable ordering and explicit truncation.
- [ ] Bound pool/retry/transaction and whole-request time; demonstrate what cancellation actually terminates.

## Blocked by

G01, Q04

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Implicit v2 acceptance, unreviewed ontology/vector choices, routing agents through GraphQL, unrelated refactors, and either complete application fixture before F99.
