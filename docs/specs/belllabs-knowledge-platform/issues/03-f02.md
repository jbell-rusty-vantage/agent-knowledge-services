# F02: Authorize one scoped knowledge read for product and external consumers

Linear: [OVE-90](https://linear.app/overtonbell/issue/OVE-90/ksp-f02-authorize-one-scoped-knowledge-read-for-product-and-external)

Status: ready-for-agent; implementation not started.

## What to build

A user and their external agent read the same permitted entity through the same application use case.

Owner: Product identity and domain API owners.

## Acceptance criteria

- [ ] Validate audience, application, tenant, actor and grants in the service layer; API-key presence is not end-user authorization.
- [ ] Apply object/field visibility and entitlements before retrieval and return consistent not-found/denied behavior.
- [ ] Separate knowledge grants from product entitlement; a content link does not grant source access.
- [ ] Test cross-app/tenant denial, expired credentials, revocation, pagination and bounded reads through HTTP and MCP.
- [ ] Keep generated database mutations and unrestricted diagnostic SQL/Cypher off the product surface.
- [ ] Keep Biotech product GraphQL, AI Engineer custom API and native agent authorization paths explicit; shared scope does not mean a shared query protocol.

## Blocked by

F01

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
