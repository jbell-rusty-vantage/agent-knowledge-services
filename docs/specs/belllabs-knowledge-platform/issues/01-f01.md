# F01: Describe and validate an application-bound knowledge installation

Linear: [OVE-88](https://linear.app/overtonbell/issue/OVE-88/ksp-f01-describe-and-validate-an-application-bound-knowledge)

Status: ready-for-agent; implementation not started.

## What to build

An operator or consumer can describe exactly which modules, native contracts and domain procedures are executable for one authenticated application.

Owner: Shared KS contracts/application and domain service owners.

## Acceptance criteria

- [ ] Resolve application/tenant from trusted identity and reject attempts to select another binding or credentials.
- [ ] Return schema, profile, policy, query, skill and operation versions plus explicit required/optional availability.
- [ ] Preserve native UID/UUID and payload canonicalization semantics in common envelopes.
- [ ] Exercise HTTP/client and MCP describe against both application profiles; missing required dependencies fail before provider effects.
- [ ] Inventory current AI Engineer coupling and expose narrow ports without changing existing read/write behavior.
- [ ] Describe native consumer routes and supported consistency/artifact semantics; do not require a universal SQL/Cypher query AST.

## Blocked by

None (can start immediately)

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
