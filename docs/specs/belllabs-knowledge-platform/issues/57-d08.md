# D08: Route maintenance proposals through affected-domain compatibility checks

Linear: [OVE-126](https://linear.app/overtonbell/issue/OVE-126/ksp-d08-route-maintenance-proposals-through-affected-domain)

Status: ready-for-agent; implementation not started.

## What to build

A public contract change produces a bounded maintenance proposal and checks the affected domain assemblies before acceptance.

Owner: Shared KS maintenance owner.

## Acceptance criteria

- [ ] Bind proposed changes and checks to exact immutable source/release fingerprints; stale source invalidates the proposal.
- [ ] Select affected consumers, skills, catalogs and release matrices from changed contracts.
- [ ] Retain independent deterministic validation even when a reviewer reports no findings.
- [ ] Preserve all retained worktrees/ignored artifacts and existing operator model policy; maintenance does not auto-deploy or mutate catalogs.
- [ ] Demonstrate changed-contract and domain-only cases using disposable Git/tooling tests.

D01, D07

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
