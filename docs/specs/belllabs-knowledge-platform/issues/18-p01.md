# P01: Compose AI Engineer user state and knowledge into a product API

Linear: [OVE-115](https://linear.app/overtonbell/issue/OVE-115/ksp-p01-compose-ai-engineer-user-state-and-knowledge-into-a-product)

Status: ready-for-agent; implementation not started.

## What to build

Web, mobile and agents can read a learner's saved work/progress with the authorized version of learning content.

Owner: AI Engineer product API owner.

## Acceptance criteria

- [ ] Provide typed user profile/preferences, saved-content/notes and progress/attempt operations with scoped revisions.
- [ ] Keep progress/notes out of canonical knowledge; private user content remains private.
- [ ] Expose content + progress composition through a generated client and minimal reference consumer view.
- [ ] Handle pagination, conflict, duplicate progress submission and offline/stale evidence explicitly.
- [ ] Document ownership and release contract for the new product host; do not claim a full absent learner application already exists.
- [ ] Implement product.project.test.request/status through an admitted execution capability with bounded workspace, exact test/rubric version, progress, cancellation and attributable result; integrate an actual external editor/workspace handoff rather than a simulated coding pane.

## Blocked by

F02, C01, R01

## Testing seam

Exercise the published consumer behavior and actual native adapter at the highest useful seam. Use targeted component, disposable integration and selected-query measurements; complete application fixtures remain restricted to F99.

## Out of scope

Unrelated refactors, accepting the entire Biotech ontology, altering immutable historical receipts, and running either complete application fixture before F99.
