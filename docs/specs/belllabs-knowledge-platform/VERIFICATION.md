## 3. Contract and pipeline

Retain `verification.v1` and its public API/MCP/CLI behavior while adding a versioned profile/control envelope. Breaking changes to assertion/support-set, response, or admission shape require new schema versions and explicit capability negotiation; never reinterpret a historical sealed v1 artifact under new rules. Names in this section describe target logical records, not already-created SQL tables or GraphQL types.

### Required input and output records

| Record | Required binding |
|---|---|
| `VerificationTaskContract` | Tenant; domain; original task revision/digest; audience; required obligations and frozen weights; cutoff/as-of; permitted sources/media; use; minimum risk; resource limits; rubric/policy versions. MC may supply task identity, but KS freezes the verification obligation artifact. |
| `AssertionVersion` | Stable logical ID plus version/digest; typed value/proposition; kind; subject/object/context bindings; qualifiers including entity, population, time, unit, jurisdiction, baseline, negation, modality; producer attempt/deployment; premise dependencies; risk reasons. |
| `AssertionOccurrence` | Assertion version; report revision/digest; exact span/coordinate basis or table/caption cell path; attribution text; obligation IDs. Identical propositions can share a support observation, but occurrences remain independently mapped and checked. |
| `EvidenceFragment` | Immutable source version, capture and representation IDs/digests; selector and normalization/resolver versions; selected digest/size; context/header/footnote bindings; parser lineage; capture completeness/access limits; tenant and rights. |
| `SupportSet` | Stable ID/digest; assertion version; member evidence edges with roles; **all-required premises within one set**; separate alternative sufficient sets. Execution-input/citation/derivation edges remain distinct from assessed support. |
| `VerificationObservation` | Append-only ID; target property/assertion/set; exact input digest; method/model/deployment/prompt/schema/configuration versions; outcome, supporting/contradicting fragment IDs, missing facets, concise rationale, limitations; acquisition frontier; timestamps; raw response artifact; usage/cost; reviewer kind/identity; failure class. |
| `AuthorityObservation` | Assertion scope; source-origin lineage and unknown frontier; authority/directness/applicability/freshness; study/method/version relevance; rights; jurisdiction; conflict/revision/retraction observations; rubric/version; evidence references; responsible assessor. |
| `CalibrationProfile` | Named event (support or use-eligibility); domain/media/risk/use slices; immutable gold/dataset/split digests; annotator/adjudicator provenance; candidate evaluator identities; fitting method; threshold; uncertainty; validity/drift triggers; promotion state. |
| `UseDecision` | Exact assertion/support-set/report/effect digest; tenant/domain/use/audience; authoritative observations; policy/rubric/calibration versions; admitted/held/rejected disposition; conditions; expiry/refresh triggers; revocation epoch; decision artifact/digest. |
| `VerificationRun` | Schema/build/runtime/dirty-state; inputs/outputs/artifact lineage; above versions/digests; predecessor/replay relation; original obligation and candidate denominators; cost ledger; operation ID; optional MC correlation; sealed manifest/bundle references. |

Required algorithm order:

1. Authenticate tenant, actor, requested use, source rights, task/rubric/policy and resource scope. Resolve existing capture bytes or acquire through approved acquisition capability.
2. Run L0 capture/representation/selector/identity/type/unit/time/arithmetic/provenance checks. Unsupported parser/media is explicit `unable_to_assess`; broken pointers do not become semantic contradictions. A deterministic failure closes semantic admission.
3. Build independently discoverable assertion occurrences and support sets. Missing citations remain in the census denominator. Qualifier loss creates a new/changed claim, not a reused pass.
4. Run evidence-only L1 on each retained externally checkable assertion's declared support set. No arbitrary network, shell, filesystem, delegation, or hidden world-knowledge authority in the judge. NLI is a bounded method candidate, not mandatory duplicate expense where unqualified.
5. Apply rule-based L2/L3 routing below. Counterevidence retrieval is a separate bounded capability: capture and register every newly found source, rerun L0, then create a new evidence-closed assessment. Keep declared-citation support separate from replacement support; rescue cannot retroactively repair the original citation.
6. Compose authority, bounded world-credibility, conflicts, and derivations. Missing evidence means unknown/unassessable, not false. Recommendations expose premises, assumptions, and decision criteria; forecasts expose horizon/assumptions. Neither receives an ordinary fact-entailed verdict.
7. Run final report census, citation correctness AND completeness, obligation coverage, cross-claim consistency, premises, qualifiers and revision-preservation checks. Added text after verification invalidates final report binding.
8. Apply domain use policy, seal the result, persist observations/decision/outbox, return exact references. At ingestion/publication recheck current revocation/freshness and exact effect/report binding transactionally.

**Support-set rule:** an assertion can pass if at least one alternative set fully supports it, but every required premise within that chosen set must be supported. Preserve contradictory evidence in other sets and let policy resolve material conflicts; selecting an easy alternative cannot hide contrary findings. A cycle among derived assertions with no grounded premises is invalid. Unknown ancestors remain explicit frontier records and hold consequential conclusions.

## 4. Verification levels, risk and domain rubrics

L0 and L1 are verification levels, not substitutes for the existing `low | medium | high | critical` impact classification. Derive minimum risk from the intended effect, consequences, uncertainty, volatility, unfamiliar modality/domain and downstream reuse. Caller-supplied lower risk cannot reduce the service-computed floor. Reuse count prioritizes investigation; it is not an independent-error probability or automatic promotion to critical.

| Risk | Minimum routing | Admission before qualified automatic calibration |
|---|---|---|
| Low | L0 + L1; sampled apparent passes receive independent audit | Official low-consequence source-attributed/engineering output requires a qualified profile or human review. Existing explicitly scoped literal-extraction exception remains only for its recorded low-risk use; it never certifies world truth or canonical facts. |
| Medium | L0 + L1; L2 for uncertain applicability, changeable facts, conflict or material inference | Hold uncertain/shifted cases; reviewed narrow attributed statements can pass with preserved qualifications. |
| High | L0 + L1 + L2 authority/counterevidence + cross-family L3; qualified human when evaluator slice is unqualified | No admission solely from agreement or raw confidence. |
| Critical | All levels, complete premises, applicability, counterevidence/frontier and qualified human sign-off | Unknown critical facts, contradictions, missing required review or unsupported media hold/fail. Human action cannot waive failed mechanics. |

A routing receipt records matched rules, risk inputs, required versus completed levels, audit inclusion probability, calls/budgets, stop reason and incomplete requirements. Budget exhaustion, missing judge, timeout or denied sensitive-input provider yields review/abstention; it never changes a required check into a pass. Sample rate is a versioned profile parameter selected from label capacity and risk; no arbitrary fixed percentage is a safety claim. Every eligible low-risk stratum has nonzero audit probability.

### Shared semantic rubric

The L1 judge answers only whether the *complete exact assertion* follows from the selected set. It checks entity and coreference, quantity/denominator/unit, population, time, baseline, negation, modality, causal wording and attribution. It must cite admitted fragment IDs and list unsupported facets. Full support, support requiring qualification, partial/context-only, contradiction, conflict, insufficient evidence and unable-to-assess remain distinguishable. Qualified support is admissible only when the qualification appears in the output occurrence and allowed-use policy. Provider output cannot choose its own family, authority, calibration state or policy.

### Domain-specific rubric artifacts

| Profile | Added checks | Examples of held conclusions |
|---|---|---|
| Educational / AI Engineer learning | Explanation and prerequisites are accurate; simplifications are declared; examples are reproducible or explicitly illustrative; cited scope and version match; learning objective coverage is separate from factual support. Pedagogical utility, clarity and learner adaptation are evaluation dimensions, not evidence truth. | A runnable toy example presented as a general production guarantee; a clear explanation with an incorrect fact; omitted prerequisite hidden by a high citation score. |
| Engineering / AI Engineer research | Official specifications can establish their own interface without a second URL; runtime/version/configuration, benchmark environment, denominator and baseline match; repository selectors bind full commit and file bytes. An executable observation binds command/toolchain/environment/inputs/exit/result artifact separately from static source support. Check operational recommendations against stated constraints. | One microbenchmark generalized to all deployments; a repository quote described as proof tests passed; stale interface documentation overriding observed version behavior. |
| Scientific / Biotech | Source report versus generalized proposition separated; study design, population/species, intervention/exposure, comparator, endpoint, sample size/denominator, uncertainty, effect measure, follow-up and limitations preserved where material. Check applicability, confounding/causality, study/product/method linkage, regulatory jurisdiction and date, revision/retraction/correction status. Same underlying study across reviews/news is one origin. Use domain-qualified evidence assessment rather than simple source counts. | Antecedent biomarker-method paper treated as commercial-product validation; association restated as causation; one-sample analytical performance presented as population/clinical utility; absent report restated as negative; corrected publication used as current without warning. |

Scientific rubric fields are required according to claim class and domain contract, not blanket extraction requirements for every document. Unreported fields stay unknown; no invented values, medical recommendations, or automatic truth classification from venue prestige. Scientific automatic promotion requires its own adjudicated slice evidence. Passing the initial engineering benchmark cannot qualify scientific admission.

## 5. Operational persistence and backend admission

### Common KS component in each application PostgreSQL deployment

Logical common records comprise operations/steps/leases/events and artifact custody, verification runs/cases/observations, provider attempts/responses/budgets/reconciliation, reviewer grants/decisions, policy/rubric/calibration artifacts, use decisions, dependency/revocation/revalidation state and projection outbox. Reuse current records and constraints before adding tables. Raw bytes live in approved object storage with authenticated handles and immutable digests; secrets, PHI and private research notes are not documentation/commit material.

Current implementations span `knowledge_service.operation`, `evidence.verification_*` and verification provider records under `orchestration.*`; see `packages/persistence/src/postgres.ts` and the database-contract workspace relations. Their existing names are not evidence that those records belong to MC. Preserve compatibility while extracting a versioned common KS component with explicit owned-object inventory. Application instances have separate databases/tenants, not one accidental cross-domain knowledge database.

**Migration authority transition:** AI Engineer's existing SQL migrations/generated types remain owned by `aiengineer/ai-engineer-db-contract` until a separately reviewed component extraction defines object ownership, versioned migration package, upgrade/backfill, compatibility, generated-type production and both deployment consumers. The KS repository must not introduce a competing migration tree. Biotech's PostgreSQL contract can consume the common component once published; it must not copy independent verification SQL. Neo4j migrations/schema remain Biotech-owned. No schema rename/move is authorized by this document alone.

MC correlation is nullable for standalone KS calls and consists of mission/work-item/attempt plus dispatch identity and KS operation/result references. A linked MC completion is execution success even when the KS use decision is held. MC cannot supply a trusted support/authority verdict or overwrite it; retry creates a recorded attempt. Keep existing KS durable execution until any later orchestration change explicitly defines lease/fencing ownership. Never run two schedulers over the same step lease.

Mandatory relational constraints, delivered through the authority above:

- Tenant-scoped composite references for run/assertion/evidence/observation/decision; immutable completed observation payloads; corrections append a new observation/version.
- Unique idempotency scope over tenant + operation kind + caller key + input digest; same key/different input rejects. Retry and cache reuse remain separately auditable.
- Artifact identity includes bytes AND admitted lineage/purpose. A content hash alone cannot import another tenant's authority or turn a caller upload into a trusted capture.
- A decision references exact policy/rubric/calibration/observation digests; admission cannot rely on mutable booleans. Reviewer decisions bind exact contested versions, reviewer grants, evidence and actor provenance.
- Transactional use-epoch check with canonical effect/publication commit; revalidation/revocation events use an outbox. Original candidate/obligation denominators persist across repair/cancellation/retry.

Biotech admission flow:

1. KS first commits the sealed result, exact use decision and durable projection outbox event in its PostgreSQL transaction. The event binds tenant, assertion/effect digest, schema PIN, decision/bundle references and authoritative eligibility epoch. A dispatch cannot precede this commit.
2. The trusted dispatcher hydrates the committed event and sealed references, authenticates ownership/integrity and obtains an eligibility observation from the PostgreSQL authority. It produces a frozen projection witness. Agents submit references; they cannot mint the witness. This observation is not a transactionally current cross-database fence.
3. The pure planner receives the witness plus graph read snapshot, schema PIN and injected time; verifies exact assertion/subject/qualifier/effect mapping and computes a deterministic plan digest. Node UID rebinding or changed predicate/value/validity requires re-verification.
4. Graph apply rechecks graph preconditions and writes source/snapshot/locator/assertion/assessment/binding plus a unique marker/receipt in the existing single `KsIntentMarker` transaction. Its initial state is a pending/native projection, not irrevocable semantic admission. Processing is idempotent by tenant + decision/effect digest. No remote call is held inside the Neo4j transaction.
5. KS verifies the acknowledgment against the committed outbox identity, graph marker/receipt, effect and decision digests, then records projection completion in PostgreSQL. Crashes and duplicate delivery reconcile against those durable records; an acknowledgment cannot resurrect a revoked decision.
6. Every official serving operation and new admitted downstream use requires a current authoritative PostgreSQL eligibility/epoch check for that exact binding. Pending, revoked, expired or mismatched bindings are excluded; when the authority or freshness cannot be established, use fails closed. The PostgreSQL check is the decision point for that operation; a later revocation controls subsequent checks and cannot retract an already completed response. Direct graph reads and cached projection state cannot independently grant official-use authority.

PostgreSQL and Neo4j have no distributed transaction. A concurrent PostgreSQL revocation may occur after dispatch eligibility was checked and before graph commit, so graph bytes may still be written after that revocation. This specification makes no claim to prevent those physical writes or to observe a transactionally current cross-database epoch. The guarantee is that a stale projection cannot authorize official serving or a new admitted use after the authoritative check observes revocation; an unavailable check holds use. Tests must distinguish physical projection presence from current semantic eligibility.

Schema/capture-only ingestion may remain available under explicitly scoped noncanonical intake policy, with candidate status and full provenance. It cannot bypass the shared verification boundary for official claims, accepted asserted effects, or publication.

## 6. Revision, contradiction and revalidation

Dependencies cover premise → derived assertion → report occurrence → use decision → graph/SQL effect → retrieval/publication. Register a use at admission, including reuse from cache. A source correction, authority/retraction change, parser/resolver change, rubric/calibration withdrawal, policy change or expired validity enqueues revalidation of the affected closure. Exact invalidation rules are versioned; unrelated branches retain their valid decisions.

Changed claims or qualifiers, context/header/footnote, arithmetic operand, selected set, report binding, or intended use require a new decision. Unchanged L0/L1 observations may be reused under section 7; final report coverage/consistency and current-use gates still run. Repair preserves the failed original and its cost/label in the candidate denominator, records changed dependency edges, and binds the new revision. Final census catches newly added factual claims and unanticipated dependencies. Dependency precision/recall is measured against seeded graphs and reviewed real revisions, not assumed complete.

## 8. Acceptance and promotion

Implementation acceptance and quality promotion are separate. Existing deterministic suites may prove bounded behavior; only independent labels can qualify semantic quality. All thresholds below are target choices for the initial noncritical technical domain, not measured results, universal safety standards, or authorization for scientific automation.

Required benchmark objects: task contract/obligations, immutable source/capture/fragment set, independently annotated occurrences/qualifiers/support sets, authority/applicability labels, expected use disposition, hard negatives, conflict/unassessable cases, revisions/dependency graph, evaluator/profile/configuration, raw output/cost and sealed manifest. Split by task/topic, source-origin family and report lineage into development, calibration, locked test and time/domain shift. Human labels are double independent and blind to candidate model/policy; domain-qualified adjudication retains original disagreement and rationale. Synthetic mutations test control behavior and are reported separately from natural-error prevalence.

| Gate | Acceptance requirement |
|---|---|
| Mechanics | All supported deterministic fixtures pass; no admitted invalid/unresolved pointer, tampered bytes/lineage, unauthorized tenant/use, same-deployment self-verification, unsupported arithmetic or stale-use race in the defined suite. |
| Census | At least 98% material occurrence recall on human gold; every designated critical occurrence found in critical fixtures. Include prose, headings, captions, tables and uncited claims. Report precision and qualifier retention. |
| Support and admission | One-sided 95% upper bound below 2% for released unsupported claims **and separately** released use-ineligible claims in initial noncritical profile. Human-unresolved assertions cannot be released as eligible. Report raw counts, natural versus mutation rates, unknowns and conservative bounds. |
| Consequential/scientific use | Critical conclusions require complete premises, disclosed inference/conflicts and qualified human sign-off. Scientific automatic scope stays unqualified until its own representative evidence and approved risk limit exist. |
| Coverage/usefulness | At least 90% frozen weighted original-question coverage and within preregistered noninferiority margin versus uniform stronger verification. Explicit evidence-limited answers may satisfy the rubric; omission cannot. |
| Candidate errors | Report candidate false acceptance among genuinely unsupported/use-ineligible candidates, including original versions later repaired/deleted; false rejection, conflict recall, supported retention and review burden. Released precision alone is insufficient. |
| Calibration | Specify support versus eligibility event, reliability/Brier/ECE and risk–coverage curves; choose thresholds on calibration only; report worst slices and shift. No raw provider-confidence threshold presented as calibrated. |
| Revision/revalidation | No designated critical regression or stale-use race; all seeded affected uses found with independent branches preserved; measure precision as well as recall and final obligation preservation. |
| Economics | Compare B0 native output, B1 mechanics, B2 single qualified small verifier, B3 uniform stronger verifier, B4 adaptive challenge/audits on paired frozen cases. Cost advantage requires a paired interval showing lower full machine cost and disclosed human-review/repair/latency change; quality must meet absolute gates. |

Pre-register task-clustered paired analysis, confidence intervals and rare-error bounds before locked evaluation. Preserve denominator definitions from the research protocol; zero denominator is not applicable. Correlated assertions are not independent Bernoulli samples. Zero observed error or an all-zero bootstrap does not establish a zero upper risk bound. If the data cannot establish a promotion gate, retain human review/narrow scope and label it **not established**. Calibration/model/rubric changes after test inspection require a new held-out qualification. Sample-size and annotation commissioning follows actual available reviewed cases and declared execution budgets; this plan invents no labels or spend authorization.
